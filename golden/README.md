# Golden takes

Labelled beatbox recordings that score the analysis pipeline (onset F1 at ±30 ms, hit-class accuracy). CI runs
`golden/golden.test.ts` on every take and fails if the scores drop more than 0.005 below `baseline.json`.

Target: 10 real takes from Eyal (+ the 2 synthetic ones generated by `npm run golden:make`).

## Files

`golden/takes/<name>.wav` + `golden/takes/<name>.json`, same name. WAV: **48 kHz**, mono (first channel is used),
16/24-bit or float. Record it with the app's spike screen ("Save last take") or any recorder with processing off.

```json
{
  "version": 1,
  "performer": "eyal",
  "device": "iPhone 15 Pro, built-in mic",
  "bpm": 92,
  "hits": [
    { "t": 0.512, "class": "kick" },
    { "t": 0.845, "class": "hatClosed" }
  ],
  "hum": [
    { "start": 0.50, "end": 1.15, "midi": 36 }
  ]
}
```

- `t`: seconds from the start of the WAV, where the hit **starts** (sorted ascending).
- `class`: `kick` · `snare` · `hatClosed` · `hatOpen` · `perc` (rim shots, tongue clicks, claps and anything else).
- `hum`: hummed bass segments for the 808 tracker (Phase 2). `midi` is optional; leave `hum: []` if there's no hum.
- `bpm` is optional (used later to score tempo).

The test rejects malformed files with a message naming the file and field.

## Labelling tip

In Audacity: add a label track, put a point label at each hit's attack with the class as its text, then
*File → Export → Export Labels*. Ask Claude to convert that export into the JSON above.

## Commands

- `npm test`: scores all takes against `baseline.json`.
- `npm run golden:update`: re-baselines after an intentional improvement (commit the new `baseline.json`).
- `npm run golden:make`: regenerates the synthetic takes (deterministic).
